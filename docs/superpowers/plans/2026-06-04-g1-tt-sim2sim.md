# G1 23DoF 乒乓 sim2sim 管线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive the trained G1 23DoF table-tennis policy through the **real C++ deploy stack** in a Python `unitree_mujoco` simulation — robot state over Unitree DDS, ball+base perception over ROS2 mocap topics — so the full sim2real pipeline is validated end-to-end before touching hardware.

**Architecture:** Python `unitree_mujoco` loads a table-tennis MJCF scene (G1 23DoF + paddle + table + ball), runs a serve controller, and publishes ball/pelvis positions over ROS2 `PoseStamped`. The unmodified DDS bridge exposes the 23 robot motors as `LowState`/`LowCmd` (domain 1). The C++ deploy binary gains a new `TableTennis` FSM state that reads robot proprioception from DDS, ball/base positions from a `RosBallSource` (rclcpp subscriber), runs `predictor.onnx` each control step, assembles the 435-dim obs through the existing `ObservationManager`, and runs `policy.onnx` → `LowCmd`.

**Tech Stack:** conda env `g1tt_sim2sim` (ROS2 Humble robostack, mujoco 3.9, unitree_sdk2py + cyclonedds, onnxruntime, rclpy), C++ deploy (unitree_sdk2 DDS + onnxruntime + rclcpp/geometry_msgs), MuJoCo MJCF.

## Background facts (verified — read before starting)

These were confirmed by reading the source; trust them rather than re-deriving:

- **Robot is G1 23DoF** (`deploy/robots/g1_23dof`, `mode_machine=4`). Physical motor count = 23, in canonical order:
  `[L_hip_pitch, L_hip_roll, L_hip_yaw, L_knee, L_ankle_pitch, L_ankle_roll, R_hip_pitch, R_hip_roll, R_hip_yaw, R_knee, R_ankle_pitch, R_ankle_roll, waist_yaw, L_shoulder_pitch, L_shoulder_roll, L_shoulder_yaw, L_elbow, L_wrist_roll, R_shoulder_pitch, R_shoulder_roll, R_shoulder_yaw, R_elbow, R_wrist_roll]`.
- The MJCF `whole_body_tracking/.../g1_description/g1_23dof_rev_1_0.xml` has its 23 `<motor>` actuators in **exactly this order** → policy joint order == MJCF actuator order == LowState motor order. Therefore `joint_ids_map = [0..22]` (identity, already in `deploy.yaml`) is correct for sim2sim. No remapping needed.
- **Perception frame** (training `tt_env.py:423-431`): `ball_pos = ball.root_link_pos_w − table.root_link_pos_w`, `robot_pos = robot.root_link_pos_w − table.root_link_pos_w` (robot **pelvis**, not torso), `heading = robot.data.heading_w` (world yaw of root). Table USD origin sits at **ground surface, table center** → place the MuJoCo table frame at world `(0,0,0)`; then published `ball_pos`/`robot_pos` are just world ball/pelvis positions.
- **heading stays sourced from IMU** in deploy via the existing `tt_heading` obs term (`tt_observations.h` reads `robot->data.root_quat_w` → yaw). `unitree_mujoco` publishes pelvis orientation as `LowState.imu_state.quaternion`, so heading is automatic — **`RosBallSource` only supplies `ball_pos` + `robot_pos`.**
- **Serve** (training `reset_ball`, `g1_tt_config` eval ranges): ball default pos env-local `(1.35, 0.0, 1.03)`; per-serve `pos_y += U(−0.1, 0.1)`; `vel = (U(−6.5,−5.0), U(−0.8,0.4), U(1.5,2.0))`; zero angular velocity. Robot init pelvis pos `(−1.6, 0.0, 0.793)`.
- **Geometry/physics targets** (IsaacSim): table `2.74 × 1.525 × 0.76` m, net at `x=0`; ball radius `0.02`, mass `0.0034` kg, restitution `0.9`; paddle restitution `0.8` (global), combine = min; paddle contact/blade center at right-wrist `+X 0.337` m, holder rolled `+90°` about `+X`.
- **Control rate**: `step_dt = 0.02` (50 Hz), matching `deploy.yaml`. Sim physics `dt` will be `0.002` (mujoco), control decimation 10.
- **Training PD gains** (IsaacLab implicit actuator, `Pingpong_TTRL/legged_lab/assets/unitree/g1.py`): with `NATURAL_FREQ=10·2π=62.83185`, `DAMPING_RATIO=2.0`:
  - `STIFFNESS_5020 = 0.003609725·NF² = 14.25`, `DAMPING_5020 = 4·0.003609725·NF = 0.907`
  - `STIFFNESS_7520_14 = 0.010177520·NF² = 40.18`, `DAMPING_7520_14 = 2.558`
  - `STIFFNESS_7520_22 = 0.025101925·NF² = 99.09`, `DAMPING_7520_22 = 6.309`
  - feet (ankle ×2) use `2×5020`: kp `28.50`, kd `1.814`.
  - Per policy-joint kp/kd (order above): `kp = [40.18,99.09,40.18,99.09,28.50,28.50, 40.18,99.09,40.18,99.09,28.50,28.50, 99.09, 14.25,14.25,14.25,14.25,14.25, 14.25,14.25,14.25,14.25,14.25]`, `kd = [2.558,6.309,2.558,6.309,1.814,1.814, 2.558,6.309,2.558,6.309,1.814,1.814, 6.309, 0.907,0.907,0.907,0.907,0.907, 0.907,0.907,0.907,0.907,0.907]`.

- [ ] **Step 2b: Add restitution via contact pairs**

MuJoCo has no direct `restitution`; bounce is governed by `solref` time-constant. Add a `<contact>` block with explicit pairs so ball/table and ball/paddle are springy (negative solref = stiffness/damping form). After `<actuator>`, add:

```xml

  <!-- negative solref => (-stiffness, -damping); high stiffness + low damping ~ high restitution -->
  <pair geom1="ball_geom" geom2="table_top"   solref="-9000 -6"  solimp="0.95 0.99 0.001"/>
  <pair geom1="ball_geom" geom2="paddle_blade" solref="-12000 -5" solimp="0.95 0.99 0.001"/>

"""Ball serve controller for the G1 table-tennis sim2sim scene.

Mirrors training `reset_ball` (Pingpong_TTRL tt_env.reset_ball) with the eval
serving ranges from g1_tt_config.G1TT_EvalEnvCfg.
"""
import numpy as np

# env-local ball default (table frame); matches BALL_CFG init_state.pos
SERVE_DEFAULT_POS = (1.35, 0.0, 1.03)
SERVE_POS_Y_RANGE = (-0.1, 0.1)      # ball.ball_pos_y_range
SERVE_VEL_X = (-6.5, -5.0)           # ball.ball_speed_x_range
SERVE_VEL_Y = (-0.8, 0.4)            # ball.ball_speed_y_range
SERVE_VEL_Z = (1.5, 2.0)             # ball.ball_speed_z_range


class Serve:
    def __init__(self, rng=None, interval_steps=150):
        # interval_steps * control_dt(0.02) = serve period; 150 -> 3 s
        self.rng = rng if rng is not None else np.random.default_rng()
        self.interval_steps = interval_steps

    def due(self, step):
        return step > 0 and step % self.interval_steps == 0

    def sample(self):
        pos = np.array(SERVE_DEFAULT_POS, dtype=np.float64)
        pos[1] += self.rng.uniform(*SERVE_POS_Y_RANGE)
        vel = np.array([
            self.rng.uniform(*SERVE_VEL_X),
            self.rng.uniform(*SERVE_VEL_Y),
            self.rng.uniform(*SERVE_VEL_Z),
        ], dtype=np.float64)
        return pos, vel
```

from rclpy.node import Node
from geometry_msgs.msg import PoseStamped

        self.ball_pub = self.create_publisher(PoseStamped, "/mocap/ball/pose", 10)

        m.pose.orientation.x = float(quat[1])
        m.pose.orientation.y = float(quat[2])
        m.pose.orientation.z = float(quat[3])
        return m

    def publish(self, ball_pos, base_pos, base_quat):
        self.ball_pub.publish(self._msg(ball_pos))
        self.base_pub.publish(self._msg(base_pos, base_quat))

```python
"""G1 table-tennis sim2sim driver.

- Loads the TT MJCF scene.
- Starts the unitree_mujoco DDS bridge (publishes LowState, applies LowCmd PD).
- Serves the ball on a fixed cadence (Serve).
- Publishes ball + pelvis positions as ROS2 PoseStamped at the 50 Hz control rate.

Run after the deploy binary is up (or before — DDS is connectionless). Domain 1.
"""
import sys
import time
import numpy as np
import mujoco
import mujoco.viewer

import rclpy
from serve import Serve
from ros_publish import MocapPublisher

# unitree_mujoco bridge: add its simulate_python dir to path (recorded in B1.1)
sys.path.insert(0, "/media/woan/84a38787-1d4e-4ba7-892e-d1d90a009a8c/lgy/unitree_mujoco/simulate_python")
from unitree_sdk2py_bridge import UnitreeSdk2Bridge  # noqa: E402
from unitree_sdk2py.core.channel import ChannelFactoryInitialize  # noqa: E402

SCENE = "/media/woan/84a38787-1d4e-4ba7-892e-d1d90a009a8c/lgy/unitree_rl_lab/deploy/robots/g1_23dof/sim2sim/scene/g1_23dof_tt_scene.xml"
DOMAIN_ID = 1
PHYS_DT = 0.002
DECIMATION = 10          # 50 Hz control / mocap publish


def main():
    model = mujoco.MjModel.from_xml_path(SCENE)
    data = mujoco.MjData(model)

    # place robot pelvis at table-frame start (free joint is first 7 qpos of pelvis)
    mujoco.mj_forward(model, data)

    ChannelFactoryInitialize(DOMAIN_ID)
    bridge = UnitreeSdk2Bridge(model, data)  # publishes LowState, applies LowCmd PD torque

    rclpy.init()
    pub = MocapPublisher()

    ball_jid = mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_JOINT, "ball_free")
    ball_qadr = model.jnt_qposadr[ball_jid]
    ball_vadr = model.jnt_dofadr[ball_jid]
    pelvis_bid = mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_BODY, "pelvis")
    ball_bid = mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_BODY, "ball")

    serve = Serve(interval_steps=150)
    ctrl_step = 0

    with mujoco.viewer.launch_passive(model, data) as viewer:
        while viewer.is_running():
            mujoco.mj_step(model, data)

            if bridge is not None:
                bridge.PublishLowState()  # method name per recorded bridge API

            if (data.time / PHYS_DT) % DECIMATION < 1:
                ctrl_step += 1
                if serve.due(ctrl_step):
                    pos, vel = serve.sample()
                    data.qpos[ball_qadr:ball_qadr+3] = pos
                    data.qpos[ball_qadr+3:ball_qadr+7] = [1, 0, 0, 0]
                    data.qvel[ball_vadr:ball_vadr+3] = vel
                    data.qvel[ball_vadr+3:ball_vadr+6] = 0.0
                # publish mocap (table frame == world frame here)
                ball_pos = data.xpos[ball_bid].copy()
                base_pos = data.xpos[pelvis_bid].copy()
                base_quat = data.xquat[pelvis_bid].copy()  # (w,x,y,z)
                pub.publish(ball_pos, base_pos, base_quat)

            viewer.sync()
            time.sleep(PHYS_DT)

    pub.destroy_node()
    rclpy.shutdown()


if __name__ == "__main__":
    main()
```

#include <atomic>
#include <memory>
#include <rclcpp/rclcpp.hpp>
#include <geometry_msgs/msg/pose_stamped.hpp>
#include "tt_ball_source.h"

// Live perception source: subscribes to the mocap topics published by the sim
// (and, on hardware, by Nokov). Drop-in replacement for ReplayBallSource.
class RosBallSource : public TTBallSource {
public:
    explicit RosBallSource(rclcpp::Node::SharedPtr node) : node_(std::move(node)) {
        ball_sub_ = node_->create_subscription<geometry_msgs::msg::PoseStamped>(
            "/mocap/ball/pose", rclcpp::SensorDataQoS(),
            [this](geometry_msgs::msg::PoseStamped::SharedPtr m) {
                bx_ = m->pose.position.x; by_ = m->pose.position.y; bz_ = m->pose.position.z;
            });
        base_sub_ = node_->create_subscription<geometry_msgs::msg::PoseStamped>(
            "/mocap/base/pose", rclcpp::SensorDataQoS(),
            [this](geometry_msgs::msg::PoseStamped::SharedPtr m) {
                rx_ = m->pose.position.x; ry_ = m->pose.position.y; rz_ = m->pose.position.z;
            });
    }

        TTPerception p;
        p.ball_pos[0] = bx_; p.ball_pos[1] = by_; p.ball_pos[2] = bz_;
        p.robot_pos[0] = rx_; p.robot_pos[1] = ry_; p.robot_pos[2] = rz_;
        p.heading = 0.0f;  // unused; heading comes from IMU (tt_heading obs term)
        return p;
    }

private:
    rclcpp::Node::SharedPtr node_;
    rclcpp::Subscription<geometry_msgs::msg::PoseStamped>::SharedPtr ball_sub_;
    rclcpp::Subscription<geometry_msgs::msg::PoseStamped>::SharedPtr base_sub_;

### Task B3.2: State_TableTennis FSM state

**Files:**
- Create: `deploy/robots/g1_23dof/include/FSM/State_TableTennis.h`

- [ ] **Step 1: Implement the TableTennis state**

Create `State_TableTennis.h`. It follows the `State_RLBase` pattern (own `ManagerBasedRLEnv`, policy thread at `step_dt`, `run()` writes processed actions to `LowCmd` via `joint_ids_map`) but additionally, **before each obs assembly**, it pulls the latest perception from `RosBallSource` into `env->tt_ball_pos`/`tt_robot_pos` and runs `TTPredictor` to fill `env->tt_ball_prediction`. Because the env's `step()` does obs→act internally, we override the loop to interleave perception + prediction (mirroring `tt_replay_main.cpp` ordering: assemble obs with the prediction from the previous step, then update the predictor after).

```cpp
#pragma once
#include <thread>
#include <chrono>
#include <memory>
#include <rclcpp/rclcpp.hpp>
#include "FSMState.h"
#include "isaaclab/envs/manager_based_rl_env.h"
#include "isaaclab/envs/mdp/observations/observations.h"
#include "isaaclab/envs/mdp/actions/joint_actions.h"
#include "isaaclab/envs/mdp/terminations.h"
#include "isaaclab/algorithms/algorithms.h"
#include "unitree_articulation.h"
#include "tt_observations.h"
#include "tt_ros_ball_source.h"
#include "tt_predictor.h"

class State_TableTennis : public FSMState
{
public:
    State_TableTennis(int state_mode, std::string state_string, rclcpp::Node::SharedPtr ros_node)
    : FSMState(state_mode, state_string)
    {
        auto cfg = param::config["FSM"][state_string];
        auto policy_dir = param::parser_policy_dir(cfg["policy_dir"].as<std::string>());

        env = std::make_unique<isaaclab::ManagerBasedRLEnv>(
            YAML::LoadFile(policy_dir / "params" / "deploy.yaml"),
            std::make_shared<unitree::BaseArticulation<LowState_t::SharedPtr>>(FSMState::lowstate));
        env->alg = std::make_unique<isaaclab::OrtRunner>(policy_dir / "exported" / "policy.onnx");

        predictor_ = std::make_unique<TTPredictor>((policy_dir / "exported" / "predictor.onnx").string(), 5);
        ball_src_ = std::make_unique<RosBallSource>(ros_node);

        registered_checks.emplace_back(std::make_pair(
            [&]() -> bool { return isaaclab::mdp::bad_orientation(env.get(), 1.0); },
            FSMStringMap.right.at("Passive")));
    }

    void enter()
    {
        // apply policy kp/kd to the matching motor indices via joint_ids_map
        auto & jmap = env->robot->data.joint_ids_map;
        for (size_t i = 0; i < jmap.size(); ++i) {
            auto & m = lowcmd->msg_.motor_cmd()[jmap[i]];
            m.kp() = env->robot->data.joint_stiffness[i];
            m.kd() = env->robot->data.joint_damping[i];
            m.dq() = 0; m.tau() = 0;
        }
        env->robot->update();

        policy_thread_running = true;
        policy_thread = std::thread([this] {
            using clock = std::chrono::high_resolution_clock;
            const std::chrono::duration<double> desired(env->step_dt);
            const auto dt = std::chrono::duration_cast<clock::duration>(desired);
            auto sleepTill = clock::now() + dt;

            env->reset();
            long t = 0;
            while (policy_thread_running) {
                // (a) refresh proprio from DDS
                env->robot->update();
                // (b) pull latest mocap perception
                auto p = ball_src_->get(t);
                env->tt_ball_pos   = Eigen::Vector3f(p.ball_pos[0], p.ball_pos[1], p.ball_pos[2]);
                env->tt_robot_pos  = Eigen::Vector3f(p.robot_pos[0], p.robot_pos[1], p.robot_pos[2]);
                // (c) assemble obs (uses tt_ball_prediction from previous step; zeros at t=0)
                auto obs = env->observation_manager->compute();
                // (d) policy -> action -> store as last_action for next step
                auto action = env->alg->act(obs);
                env->action_manager->process_action(action);
                // (e) update predictor AFTER the step for t+1 (training order)
                auto pred = predictor_->update({p.ball_pos[0], p.ball_pos[1], p.ball_pos[2]});
                env->tt_ball_prediction = Eigen::Vector3f(pred[0], pred[1], pred[2]);

                std::this_thread::sleep_until(sleepTill);
                sleepTill += dt;
                ++t;
            }
        });
    }

    void run()
    {
        auto action = env->action_manager->processed_actions();
        auto & jmap = env->robot->data.joint_ids_map;
        for (size_t i = 0; i < jmap.size(); ++i)
            lowcmd->msg_.motor_cmd()[jmap[i]].q() = action[i];
    }

    void exit()
    {
        policy_thread_running = false;
        if (policy_thread.joinable()) policy_thread.join();
    }

private:
    std::unique_ptr<isaaclab::ManagerBasedRLEnv> env;
    std::unique_ptr<TTPredictor> predictor_;
    std::unique_ptr<RosBallSource> ball_src_;
    std::thread policy_thread;
    bool policy_thread_running = false;
};
```

> NOTE: `State_TableTennis` takes a `rclcpp::Node` in its ctor, so it is NOT registered via the parameter-free `REGISTER_FSM` macro used by the stock states. It is constructed explicitly in `main.cpp` (B3.4) and added to the FSM.
